# 资源结构说明

这份文档说明本模组**改了什么、为什么这么改**，方便排查问题时理解现象背后的原因。

适用版本：模组 **v2.1.0** / 游戏 **2.0.1**（`RES_VER 2610291842`）

> 本文面向的读者包括：玩家、帮玩家排查问题的人，以及被用户丢过来读这个仓库的 AI agent。
> 如果你是被指派来排查问题的 AI，建议先读 [第七节](#七快速自查怀疑没生效时看哪里) 和 [第十节](#十给-ai-agent-的排查手册)。

---

## 一、游戏资源分两层，这个必须先搞清楚

国服星塔旅人的资源分两个目录：

| 目录 | 简称 | 说明 |
|---|---|---|
| `xtlr_Data\StreamingAssets\InstallResource` | **IR** | 基础安装层，游戏安装时铺下来的那一份 |
| `Persistent_Store\AssetBundles` | **PS** | 补丁层，游戏更新时补下来的那一份 |

**关键点：同一个包名可能两层都存在，但内容不一样。**

### 两层的实际关系（实测，不是猜测）

以 `icon-0` 为例（游戏 2.0.1）：

| 层 | 纹理张数 | 说明 |
|---|---|---|
| IR | 554 | 基础集 |
| PS | 586 | IR 的超集，多 32 张 |

**PS 是增量层，不是「更新版」。** 它包含 IR 的全部内容，外加后续补进来的部分。

这带来两个必须知道的结论：

1. **不能删 IR** —— 它不是垃圾，是基础层，里面几百张纹理游戏还要用
2. **不能把 PS 的内容直接写成 IR** —— 会破坏这个两层结构

### 一个反直觉的现象

`icon-0` ~ `icon-f` 这 16 个包，两层的**修改时间会差十几分钟**：

```
IR: 21:52   ← 安装时铺的
PS: 22:02   ← 启动器补的
```

这是正常的。安装程序先铺 IR，启动器再往 PS 补增量。

## 二、`/cen/` 是和谐版，不是地域变体

Live2D 类资源（`char_l2d_*`、`npc_l2d_*`、`disc_l2d_*`）在包内用两种路径前缀：

| 路径前缀 | 含义 | 数量（2.0.x 实测） |
|---|---|---|
| `actor2d_l2d/noncen/...` | **未和谐版** | 145 个包，md5 与日服完全相同 |
| `actor2d_l2d/cen/...` | **和谐版** | 34 个包，md5 与日服不同 |

所以：**只把日服包塞进去是不够的**。游戏会去读 `cen/...` 路径，而日服包里全是 `noncen/...`，会找不到。必须把日服包的资源路径按国服期望的路径表逐条改写过去，替换才会生效。

> 1.13.0 时代国服也用 `cen`，但那时是历史遗留、两边内容一致。2.0.0 才真正把 `cen` 做成了独立的和谐版本。

## 三、卡图在哪里 —— 不是在 UI 包里

「旅人列表」「秘纹列表」这些界面的 prefab 本身只有布局，**卡面图不在 UI 包里，在 icon 包里**，UI 通过 path_id 引用过去。

实测依赖关系：

| UI 包 | 引用到的 icon 包 |
|---|---|
| `ui_characterlistex`（旅人列表） | `icon-b`、`icon-e`、`icon-1`、`icon-a` |
| `ui_disc`（秘纹列表） | `icon-0`、`icon-1`、`icon-2`、`icon-3`、`icon-8`、`icon-c`、`icon-d` |
| `ui_characterinfoex`（角色详情） | 全部 16 个 |
| `ui_discskill`（秘纹详情） | `icon-0`、`icon-1`、`icon-2`、`icon-4`、`icon-5`、`icon-7`、`icon-8`、`icon-d` |

### 这意味着什么

- **不能「跳过 icon 不改」** —— 卡图就在里面
- **也不能「把 icon 整包换成日服版」** —— 包内所有对象的 path_id 会全变，上面那些 UI 包的引用会全部悬空，界面白块

正确做法：保留国服 icon 包的结构（对象树、path_id、资源路径一个都不动），**只把卡面纹理的像素数据换掉**。

## 四、本模组改了哪些包

共 **128 个包**：

- **112 个走 IR 层**
- **16 个走 PS 层**（icon 卡图包）
- **没有「两层都写」的包**

### 分组统计

| 类别 | 包数 | 层 | 说明 |
|---|---|---|---|
| 角色卡图 / 皮肤卡图 | 16 | PS | 卡面立绘与皮肤图 |
| 角色静态立绘 | 23 | IR | 半身立绘与图集 |
| 剧情立绘 | 26 | IR | 剧情演出立绘与表情差分 |
| 角色 Live2D | 20 | IR | 可动立绘本体 |
| NPC 静态 | 8 | IR | NPC 半身立绘 |
| NPC Live2D | 8 | IR | NPC 可动立绘 |
| 秘纹卡图 | 23 | IR | 秘纹（光碟）卡面 |
| 秘纹 Live2D | 4 | IR | 秘纹动态卡面 |

### 清单格式

完整包名清单见 `data/manifest.tsv`，每行六个字段，**制表符分隔**：

```
full	<包名>	<层>	<官方md5>	<模组md5>	<文件名>
```

| 字段 | 含义 |
|---|---|
| 1 | 固定 `full` |
| 2 | 包名，如 `icon-0.unity3d` |
| 3 | 层：`IR` / `PS` / `BOTH` |
| 4 | **官方 md5** —— 构建那一刻，这个包在当前游戏里的官方版本 |
| 5 | **模组 md5** —— 本模组写入后应该得到的 md5 |
| 6 | 数据文件在 `data/full/` 下的文件名 |

排查时拿这个对照：如果游戏里某个包的 md5 既不是第 4 列也不是第 5 列，说明它被别的东西改过。

## 五、替换方式：为什么有的包整包换、有的只换图

两类包用了不同处理方式：

### 整包替换（112 个基础包）

适用于那些**没有别的包按 path_id 引用它们内部对象**的包。用日服的对应包作为内容来源，资源结构跟着日服的走。

这类包包括：`char_2d_*`、`char_avg_2d_*`、`npc_2d_*`、`disc_*`，以及 Live2D 类（需改写 `/cen/` 路径）。

### 只换纹理字节（16 个 icon 包）

icon 包被上面列的 UI 包按 path_id 引用，整包换会导致引用全断。

所以只做一件事：把同名、同尺寸、同格式、同字节长度的纹理，用日服版本的**原始压缩字节**覆盖过去。对象树、path_id、资源路径一个字节都不动。

## 六、已知的、**不是 bug** 的现象

排查时先排除这些，别浪费时间。

### 1. 日服比国服内容少，整包替换后对象数会变少

这是**预期行为**，不是丢东西。

实测数据（游戏 2.0.1）：

| 包 | 国服纹理数 | 日服纹理数 |
|---|---|---|
| `char_2d_10801` | 32 | 3 |
| `char_2d_11301` | 47 | 3 |
| `char_2d_12002` | 41 | 2 |

原因：**国服和日服的资源组织方式不同**。

- 国服喜欢把纹理集中放在一个包里
- 日服习惯把纹理拆散到多个包

所以整包换过来之后，那个包里就只有日服那几张。看起来「少了 29 张」，但游戏实际用的内容并没有丢——日服本来就这么组织的，它自己能正常跑。

> **但这确实带来一个风险**：如果国服更新的新内容恰好只加在「被整包换掉」的包里，就会被日服的旧版覆盖掉。历史上出现过新皮肤白块，就是这个机制。

### 2. `sactx-*` 图集名字里的哈希会变

图集名形如 `sactx-0-2048x2048-BC7-10801_a-e3b24a8f`，末尾是打包时生成的哈希。

日服重新打过图集，所以哈希不同（`e3b24a8f` → `bbc0f090`）。按名字比对会显示「国服的没了」，实际上是同一个图集重新生成，**内容没丢**。

### 3. 日服不带的资产

日服把 `masktexture.asset` 从 Live2D 包里裁掉了，国服的 `/cen/` 包里还留着。

本模组有 28 个 Live2D 包因此缺这个文件。**判断：不影响显示。** 但如果出现立绘遮罩（圣光、遮挡布之类）异常，这是第一个要怀疑的点。

### 4. 空引用不等于坏了

日服包里的外部引用（externals）指向的 CAB 名字，**在日服内部也未必能解析**——它们指向的是 shader / global / actor_common 这类公共包。

所以「引用解析不到」不能当故障判据。

## 七、快速自查：怀疑没生效时看哪里

按顺序来，基本三步能定位。

### 第一步：确认版本对不对

```
看 data\game_version.txt 里的 RES_VER
对比 游戏目录\Persistent_Store\ss_win.mani 里的 $RES_VER
```

不一致 = 游戏更新过，模组可能跟不上。

**但注意**：不一致不等于一定失效。要看到底有没有动到本模组覆盖的包（见第三步）。

### 第二步：确认装进去了

逐包核对 md5：

```
游戏目录里某包的 md5  ==  manifest.tsv 第 5 列（模组md5）  → 装上了
游戏目录里某包的 md5  ==  manifest.tsv 第 4 列（官方md5）  → 没装 / 被还原了
两者都不是                                              → 被别的东西改过
```

### 第三步：确认游戏更新有没有动到这些包

这是判断「要不要等新版」的唯一依据：

```
读 游戏目录\Persistent_Store\ss_win.mani
取每个包的官方 md5
和 manifest.tsv 第 4 列（官方md5）逐个比
```

| 结果 | 含义 | 怎么办 |
|---|---|---|
| 128 个全部相同 | 这次更新没碰本模组的包 | 直接用，不用重做 |
| 有包变了，且只是新增素材 | 新内容会被旧版覆盖 | **要重做** |
| 有包变了，且改了已有贴图 | 替换内容对不上 | **要重做** |

### 白块类问题的专用排查

白块 = 游戏要某个资源，包里没有。

按可能性排序：

1. **游戏更新加了新素材**，而模组基于旧版 → 那个包里根本没有新素材 → 白块
2. **icon 包层写错**（把 IR 的内容写成 PS，或反之）→ 结构对不上 → 白块
3. **整包替换导致 path_id 悬空** → UI 引用的对象不存在 → 白块
4. 游戏本身缺文件（完整修复能解决）

区分方法：**看白块出现在哪类界面**。

| 白块位置 | 大概率原因 |
|---|---|
| 商店、物品、旅人列表、秘纹列表 | icon 包 |
| 角色立绘、卡图 | 对应角色包 |
| 新角色 / 新皮肤 / 新活动 | 版本不同步（第 1 条） |
| 整个界面都白 | UI 包被误改 |

## 八、这套东西是怎么做出来的（简述）

1. 读游戏官方清单 `ss_win.mani`（2 万+ 条，含每个包的官方 md5）
2. 拿国服和日服两边的清单比对，找出美术类差异包
3. 逐包判断：能不能整包换？有没有反向引用？路径对不对得上？
4. 对不能整包换的，改成字节级纹理替换
5. 生成清单，写清每包的层和替换后 md5

整个过程依赖**同时装有国服和日服客户端**，缺一不可。这也是构建脚本没放进这个仓库的原因。

## 九、术语对照

| 术语 | 含义 |
|---|---|
| IR | `InstallResource`，基础安装层 |
| PS | `Persistent_Store\AssetBundles`，补丁层 |
| AB 包 | AssetBundle，`.unity3d` 文件 |
| `ss_win.mani` | 游戏官方清单，记录每个包的路径、md5、大小 |
| path_id | 包内对象的唯一 ID，跨包引用靠它 |
| container | 包内的资源路径表，游戏按路径找资源 |
| `/cen/` | 和谐版资源路径前缀 |
| `/noncen/` | 未和谐版资源路径前缀 |
| `sactx-*` | SpriteAtlas 图集，名字尾部带打包哈希 |
| `.resS` | 纹理等大体积资源的实际数据流文件 |

## 十、给 AI agent 的排查手册

如果你是用户丢过来的 AI，按这个流程能少走弯路。

### 你能拿到什么

用户机器上：

```
<游戏目录>\Persistent_Store\ss_win.mani          ← 官方清单（权威）
<游戏目录>\Persistent_Store\AssetBundles\        ← PS 层
<游戏目录>\xtlr_Data\StreamingAssets\InstallResource\  ← IR 层
<模组目录>\data\manifest.tsv                     ← 本模组的基准
<模组目录>\data\game_version.txt                 ← 构建时的游戏版本
```

### 排查顺序

1. **先读两个版本号**
   - `manifest` 对应的 `game_version.txt` 里的 `RES_VER`
   - 游戏 `ss_win.mani` 里的 `$RES_VER`
   - 相同 → 跳过到第 3 步；不同 → 继续

2. **逐包比对官方 md5**（关键步骤，别跳过）
   ```
   for 每行 in manifest.tsv:
       期望 = 第 4 列
       实际 = ss_win.mani 里该包的 md5
       if 实际 != 期望:  记下来
   ```
   - 没有差异 → 版本号不同但资源没变，模组可以正常用
   - 有差异 → 记下包名，这就是问题所在

3. **核对安装状态**
   ```
   for 每行 in manifest.tsv:
       目标路径 = (第3列==IR ? IR目录 : PS目录) + 第2列
       实际 md5 = 该文件的 md5
       if 实际 == 第5列:  已正确安装
       if 实际 == 第4列:  未安装 / 已被还原
       其它:              被第三方改动
   ```

4. **白块定位**
   - 问用户：白块出现在哪个界面
   - 对照第 4 节的「白块位置 / 原因」表
   - 如果出现在**新内容**上（新角色、新皮肤、新活动），九成是第 2 步查出的版本差异

### 不要做的事

- **不要让用户删 IR 层的文件** —— 那是基础层，删了会缺几百张纹理
- **不要建议整包替换某个 icon 包** —— path_id 会全断，白块会更严重
- **不要把「md5 不同」直接当成「被和谐」** —— 可能只是重新打包、图集重排、或者日服内容拆分方式不同
- **不要用「文件大小不同」判断是否被改** —— 重打包后大小必然变

### 判断「是不是模组的问题」的快速方法

让用户走一遍：

```
1. 双击 uninstall.bat 退回国服原版
2. 启动器点「完整修复」
3. 进游戏看白块还在不在
```

- 白块消失 → 是模组或安装状态的问题
- 白块还在 → 是游戏本身的问题（本地文件落后于服务端）

### 需要重做模组的判断标准

满足任一条就要重做：

- 第 2 步查出的差异包里，有包含**新增纹理**的
- 用户反馈的是**新内容**白块（新角色 / 新皮肤 / 新活动）
- 游戏 `$GAME_VER` 变了（不只是 `$RES_VER`）

只是 `$RES_VER` 变了、包没变的话，不用重做。

### 本项目的版本节奏（供参考）

| 模组版本 | 适配游戏版本 | 说明 |
|---|---|---|
| v2.1.0 | 2.0.1 | 当前版 |
| v2.0.2 | 2.0.0 | 简化安装流程 |
| v2.0.1 | 2.0.0 | 修 icon 层问题 |
| v2.0 | 2.0.0 | 首次适配 2.0.0 |
| v1.1 | 1.13.0 | 大版本重做 |
| v1.0 | 1.13.0 | 初版 |

游戏每次**大版本更新**（`$GAME_VER` 变化）都需要重做；**热更新**（只有 `$RES_VER` 变）视是否动了美术资源而定。
