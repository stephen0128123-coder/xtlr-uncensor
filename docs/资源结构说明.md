# 资源结构说明

这份文档说明本模组**改了什么、为什么这么改**，方便排查问题时理解现象背后的原因。

适用版本：模组 v2.0 / 游戏 2.0.0

---

## 一、游戏资源分两层，这个必须先搞清楚

国服星塔旅人的资源分两个目录：

| 目录 | 简称 | 说明 |
|---|---|---|
| `xtlr_Data\StreamingAssets\InstallResource` | **IR** | 基础安装层，游戏安装时铺下来的那一份 |
| `Persistent_Store\AssetBundles` | **PS** | 补丁层，游戏更新时补下来的那一份 |

**关键点：同一个包名可能两层都存在，但内容不一样。**

游戏读取时优先看 PS，PS 没有才回落到 IR。

### 2.0.0 的一个特殊现象

`icon-0` ~ `icon-f` 这 16 个图标包，两层的状态是这样的：

| 层 | 内容 | 状态 |
|---|---|---|
| PS | 官方 2.0.0 版 | ✅ 是当前版本 |
| IR | 1.13.0 时代遗留的旧文件 | ❌ 没被 2.0.0 更新覆盖 |

原因：2.0.0 大版本更新时，这 16 个包的新版只放进了 PS 层，IR 层留着旧文件没动。

**这带来一个后果**：如果往 IR 层写一个「基于旧文件改出来的」版本，虽然 PS 层没被动，但一旦清单写成「两层都写」，就会把 PS 层的 2.0.0 新版**整个覆盖成旧版**——2.0.0 才有的贴图全部消失，界面上就是一片白块。

本模组因此对 icon 包做了特殊处理：**以 PS 层的官方文件为基底修改，只写 PS 层，IR 层完全不动。**

## 二、`/cen/` 是和谐版，不是地域变体

Live2D 类资源（`char_l2d_*`、`npc_l2d_*`、`disc_l2d_*`）在包内用两种路径前缀：

| 路径前缀 | 含义 | 数量（2.0.0 实测） |
|---|---|---|
| `actor2d_l2d/noncen/...` | **未和谐版** | 145 个包，md5 与日服完全相同 |
| `actor2d_l2d/cen/...` | **和谐版** | 34 个包，md5 与日服不同 |

这个对应关系在 2.0.0 里没有反例。

所以：**只把日服包塞进去是不够的**。游戏会去读 `cen/...` 路径，而日服包里全是 `noncen/...`，会找不到。必须把日服包的资源路径按国服期望的路径表逐条改写过去，替换才会生效。

> 1.13.0 时代国服也用 `cen`，但那时是历史遗留、两边内容一致。2.0.0 才真正把 `cen` 做成了独立的和谐版本。

## 三、卡图在哪里 —— 不是在 UI 包里

「旅人列表」「秘纹列表」这些界面的 prefab 本身只有布局，**卡面图不在 UI 包里，在 icon 包里**，UI 通过 path_id 引用过去。

实测依赖关系：

| UI 包 | 引用到的 icon 包 |
|---|---|
| `ui_characterlistex`（旅人列表） | `icon-b`、`icon-e`、`icon-1`、`icon-a` |
| `ui_disc`（秘纹列表） | `icon-0`、`icon-1`、`icon-2`、`icon-3`、`icon-8`、`icon-c`、`icon-d` |
| `ui_characterinfoex`（角色详情） | 全部 16 个 |
| `ui_discskill`（秘纹详情） | `icon-0`、`icon-1`、`icon-2`、`icon-4`、`icon-5`、`icon-7`、`icon-8`、`icon-d` |

### 这意味着什么

- **不能「跳过 icon 不改」** —— 卡图就在里面，不改卡图就没变
- **也不能「把 icon 整包换成日服版」** —— 包内所有对象的 path_id 会全变，上面那些 UI 包的引用会全部悬空，界面白块

正确做法：保留国服 icon 包的结构（对象树、path_id、资源路径一个都不动），**只把卡面纹理的像素数据换掉**。

## 四、本模组改了哪些包

共 **128 个包**：

- **112 个走 IR 层**
- **16 个走 PS 层**（就是上面说的 icon 卡图包）
- **没有「两层都写」的包**

### 分组统计

| 类别 | 包数 | 层 | 说明 |
|---|---|---|---|
| 角色卡图 / 皮肤卡图 | 16 | PS | 卡面立绘与皮肤图 |
| 角色静态立绘 | 23 | IR | 半身立绘与图集 |
| 剧情立绘 | 26 | IR | 剧情演出立绘与表情差分 |
| 角色 Live2D | 20 | IR | 可动立绘本体 |
| NPC 静态 | 8 | IR | NPC 半身立绘 |
| NPC Live2D | 8 | IR | NPC 可动立绘 |
| 秘纹卡图 | 23 | IR | 秘纹（光碟）卡面 |
| 秘纹 Live2D | 4 | IR | 秘纹动态卡面 |

完整包名清单见 `data/manifest.tsv`，每行的字段是：

```
full	<包名>	<层>	<官方md5>	<模组md5>	<文件名>
```

排查时拿这个对照：如果游戏里某个包的 md5 既不是「官方md5」也不是「模组md5」，说明它被别的东西改过。

## 五、替换方式：为什么有的包整包换、有的只换图

两类包用了不同处理方式，原因不同：

### 整包替换（大部分）

适用于那些**没有别的包按 path_id 引用它们内部对象**的包。直接把日服对应包的内容搬过来，资源结构跟着日服的走。

这类包包括：`char_2d_*`、`char_avg_2d_*`、`npc_2d_*`、`disc_*`、以及 Live2D 类（需改写 `/cen/` 路径）。

### 只换纹理字节（icon 系列）

icon 包被上面列的那一堆 UI 包按 path_id 引用。整包换会导致引用全断。

所以只做一件事：把同名、同尺寸、同格式、同字节长度的纹理，用日服版本的**原始压缩字节**覆盖过去。对象树、path_id、资源路径一个字节都不动。

> 这也是为什么「换个包」这种事看起来简单，实际上要按包区别对待。

## 六、日服 2.0.0 少了一个资产

日服 2.0.0 把 `masktexture.asset` 这个资产从 Live2D 包里裁掉了，国服的 `/cen/` 包里还留着。

本模组有 28 个 Live2D 包因此缺这个文件。

**判断：不影响显示。** 日服自己不带这个东西也能正常运行。但如果出现立绘遮罩（圣光、遮挡布之类）显示异常，这是第一个要怀疑的点。

---

## 七、快速自查：怀疑没生效时看哪里

1. **先看 `data/game_version.txt`** 里的 `RES_VER` 和游戏 `Persistent_Store\ss_win.mani` 里的 `$RES_VER` 是不是一致
   - 不一致 = 游戏更新过了，模组跟不上，必然无效
2. **看 `tools\precheck.bat` 的输出**，它会逐包核对 md5
3. **对比 `data/manifest.tsv`**：某包的 md5 如果不是「模组md5」，就是没装上
4. **白块类问题**优先查 icon 包的层：PS 层被写成 IR 层的旧内容就会白

---

## 八、这套东西是怎么做出来的（简述）

1. 读游戏官方清单 `ss_win.mani`（21162 条，含每个包的官方 md5）
2. 拿国服和日服两边的清单比对，找出美术类差异包
3. 逐包判断：能不能整包换？有没有反向引用？路径对不对得上？
4. 对不能整包换的，改成字节级纹理替换
5. 生成清单，写清每包的层和替换后 md5

整个过程依赖**同时装有国服和日服客户端**，缺一不可。
